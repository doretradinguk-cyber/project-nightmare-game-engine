## Known limitations / errors
1. Folder import/build requires a browser supporting the File System Access API and a secure context; browsers without it can use the file-input fallback and export the generated manifest, but cannot silently write a complete pack directory.
2. SHA-256 is generated by reading each selected file into memory; very large assets should later move to a worker/native build pipeline.
3. Licence approval is intentionally conservative: a licence reference not present in `data/licences/approved.json` blocks a release pack.
4. The browser builder writes ordinary folders/manifests, not a proprietary binary archive.
5. Android mapping is metadata only at this stage; the actual Gradle/Play Asset Delivery project is the next native-platform task.
6. Three.js remains a jsDelivr development import; release should vendor/pin it and retain the MIT notice.
7. Physical Android hardware testing has not been performed.
